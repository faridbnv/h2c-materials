# The must-not-change map

> **In short.** The remake may change storage, packaging and tooling. It may not change what the tool says about a material unless you rule that it should. This page lists every non-negotiable (14 from the current-state report, 24 from the science brief) and says which test, gate or parity tier holds each one today. Where nothing holds it, or only part of it, the row says so in capitals. 29 rows are fully tested, 9 are partly tested and none has no test. Your list of the 9 partial rows is in [untested-rules.md](untested-rules.md); the three rows that tests have closed since the list was written (S11-07, S06-06, S11-10) are kept there, marked, for you to confirm. The links between this page and the check register are verified by `npm run checks:register -- --verify`: delete a test named below and the check fails.

## How to read a row

| Column | Meaning |
|---|---|
| ID | `S11-nn` is a row of the current-state report, section 11. `S06-nn` is a row of the science brief, section 3. Several rows say the same thing twice, on purpose: each source list is mapped in full. |
| Rule | The rule in short. The full wording and the decision numbers are in the source list and `docs/DECISIONS.md`. |
| Old suite | Tests (`test/...`), gates (`step:`, `ci:`, `npm:`) of the old tool that hold the rule today. They stay on `main` until cutover and are frozen on this branch. |
| New suite and parity | Tests under `tests/`, and parity tiers that run today. `P-engine` compares the old and the new engine on 1,306 corpus questions (decision, presentation, evidence, wording). `P-erase` compares code before and after type erasure. Tiers not built yet (`P-build`, `P-pages`, `P-ui`, `P-data`) are named in the note, not counted as protection. |
| Status | TESTED: a named check asserts the rule. PARTIAL: a named check asserts part of it, and the note says what nothing checks. UNTESTED: nothing asserts it. |
| Gap or note | What is not covered, or what a reader should know. Required for PARTIAL and UNTESTED. |

A named test pins the rule only as far as its title says. The register (`checks/register.csv`) records, for each check, the failure it protects and its successor.

## How this page is kept honest

- `npm run checks:register -- --verify` reads this page. It fails if an item is missing, if a test, gate or parity tier named here does not exist or is not built, if an item has neither a named check nor an UNTESTED mark, if the check register does not say that the check protects the item, or if [untested-rules.md](untested-rules.md) does not list every PARTIAL and UNTESTED item.
- An item moves from PARTIAL or UNTESTED to TESTED by naming the new test in the row, in the same change that adds the test and its register row. It never moves because someone decided the gap is acceptable: that is a ruling in `docs/next/rulings.csv`.
- A parity tier counts as protection only when it runs. `P-build`, `P-pages`, `P-ui` and `P-data` are added to the list of built tiers in `remake/tools/checks-register.mjs` by the work package that builds them.
- Parity compares the new tool with the old one on a fixed corpus. It does not prove an old answer is right, and it sees nothing outside the corpus. A row that names only `P-engine` for a rule the corpus may not exercise is marked in the note.
